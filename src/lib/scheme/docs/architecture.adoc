== Obiettivo

Visualizzare e tracciare l'evoluzione di un programma Scheme come sequenza deterministica di trasformazioni dell'Albero Sintattico Astratto (AST) e dello stato degli ambienti di calcolo fino al raggiungimento della forma normale irriducibile.

== Pipeline principale

[source,text]
----
Codice Sorgente Scheme
  -> Lexer (analizzatoreLessicale -> Parola[])
  -> Parser (ParserScheme -> ProgrammaAST)
  -> Stepper (StepperScheme -> PassoStepping[] / passiStream)
  -> Formatter (FormatterScheme -> SnapshotPassoStepping[])
  -> Visualizzazione UI Web / CLI Output
----

== Componenti Principali

=== Lexer (`src/lib/scheme/lexer/`)

**Responsabilità:**

- Tokenizzazione del codice sorgente Scheme tramite `analizzatoreLessicale`.
- Riconoscimento di tipi di token (`TipoDiParole`): Parentesi, Booleani (`#t`, `#f`), Numeri, Stringhe, Simboli, Citazione (`'`), Punto (`.`), Commenti (ignorati).
- Tracciamento della posizione dei token nel sorgente per messaggi di errore ed ispezione.

**Output:** Sequenza ordinata di token (`Parola[]`) terminata dal token sintetico `FineDelFile`.

=== Parser (`src/lib/scheme/ast/parser.ts`)

**Responsabilità:**

- Parsing top-level a discesa ricorsiva da token a `ProgrammaAST`.
- Parsing delle forme speciali tipizzate:
  * `DefineAST`: definizioni di variabili e funzioni (`define`, `definisci`).
  * `LambdaAST`: espressioni di chiusura di funzione (`lambda`).
  * `IfAST`: condizionale binario (`if`, `se`).
  * `AndAST`: congiunzione logica a n-argomenti con cortocircuito (`and`, `e`).
  * `OrAST`: disgiunzione logica a n-argomenti con cortocircuito (`or`, `o`).
  * `CondAST`: condizionale multi-ramo con clausole e ramo `else` / `altrimenti`.
  * `CitazioneAST`: citazioni di atomi, liste e coppie puntate (`quote`, `cita`, `'`).
  * `ApplicazioneAST`: chiamate di funzione e primitive.
- Sollevamento di `SyntaxError` strutturati in caso di sintassi non valida.

**Output:** Albero AST radice `ProgrammaAST` navigabile via Visitor pattern.

=== Ambienti di Calcolo (`src/lib/scheme/runtime/ambiente*.ts`)

**Responsabilità:**

- Gestione dello scope lessicale gerarchico (parent/child) tramite la classe `Ambiente<ValoreScheme>`.
- Risoluzione dei simboli con ricerca ricorsiva lungo la catena di ambienti.
- Generazione di istantanee dello stato (`SnapshotAmbiente` e `SnapshotScopeAmbiente`) serializzate per ogni passo.
- Registro profili d'ambiente predefiniti via `creaAmbiente(id)` e `registroAmbienti`:
  * `"standard"`: include lista vuota, primitive aritmetiche, logiche e predicati di lista.
  * `"minimo-numeri-naturali"`: sottoinsieme minimo per aritmetica Peano (`zero?`, `s`, `p`).
  * `"nat-add-sot-min"`: aritmetica estesa per algoritmi di divisione.

=== Stepper (`src/lib/scheme/runtime/stepper.ts`)

**Responsabilità:**

- Riduzione a piccoli passi (*small-step reduction*) di un nodo AST o dell'intero `ProgrammaAST`.
- Esecuzione del ciclo di riduzione:
  1. Risoluzione dei simboli nello scope corrente.
  2. Valutazione left-to-right degli argomenti nelle applicazioni.
  3. Riscrittura sostitutiva delle clausole per `if`, `and`, `or`, `cond`.
  4. Applicazione di funzioni primitive TypeScript (`FunzionePrimitiva`).
  5. Riscrittura lambda con sostituzione dei parametri formali (`Chiusura`).
- Generazione della sequenza di `PassoStepping` contenente `astPrecedente`, `astSuccessivo`, `regolaApplicata`, `èTerminato` e lo `SnapshotAmbiente`.
- Supporto sia per la timeline completa (`passiDaSorgente`) sia per la fruizione pigra/streaming (`passiStream`).

=== Formatter (`src/lib/scheme/ast/formatter.ts`)

**Responsabilità:**

- Rendering simbolico canonico in stringa Scheme per ogni nodo AST tramite `FormatterScheme` (Visitor).
- Conversione dei `PassoStepping` nei DTO di snapshot (`SnapshotPassoStepping`) per l'integrazione frontend.
- Generazione di tracce testuali lineari per il debugging ed il tracciamento via CLI.

== Principi Architetturali

- **Determinismo:** L'esecuzione di uno stesso sorgente produce una sequenza identica e riproducibile di passi e istantanee.
- **Tracciabilità:** Ogni riscrittura dell'AST è accompagnata da una stringa descrittiva esplicita della regola applicata.
- **Isolamento dei Moduli:** Lexer, Parser, Stepper, Ambienti e Formatter sono disaccoppiati e testati in modo indipendente.
- **Type Safety:** Uso rigoroso di tipi TypeScript per valori (`ValoreScheme`), nodi AST e stati dell'ambiente.
