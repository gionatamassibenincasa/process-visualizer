= Error Model
:toc: left
:toclevels: 3
:sectnums:

== Scopo

Uniformare la classificazione, il formato ed il trattamento degli errori generati dall'interprete Scheme (`ParserScheme`, `StepperScheme`, `Ambiente`), facilitando il logging ed il rendering strutturato dei messaggi di errore nella UI web.

== Categorie di Errore

=== 1. `SYNTAX_ERROR` (Errori Sintattici)

**Origine:** `ParserScheme` (`src/lib/scheme/ast/parser.ts`)

Lanciati come istanze di `SyntaxError` quando il codice sorgente viola le regole grammaticali EBNF.

**Formato del messaggio:**
`SyntaxError: <messaggio>. Token corrente: <valore> (<tipo>).`

**Esempi:**
- Parentesi aperta o chiusa mancante (`"Attesa parentesi chiusa..."`).
- Nome non simbolico in `define` (`"Il nome in define deve essere un simbolo."`).
- Parametri `lambda` non validi (`"I parametri lambda devono essere simboli."`).
- Corpo `lambda` vuoto (`"Il corpo lambda non puo essere vuoto."`).
- Clausola `cond` senza conseguente (`"Ogni clausola cond deve avere almeno un conseguente."`).

=== 2. `UNDEFINED_SYMBOL` (Simbolo Non Definito)

**Origine:** `Ambiente.applica` (`src/lib/scheme/runtime/ambiente.ts`)

Lanciato come `Error` standard quando lo stepper tenta di valutare o applicare un identificatore non presente nell'ambiente locale o nei relativi genitori.

**Formato del messaggio:**
`Errore di Runtime: Simbolo '<simbolo>' non definito nello scope.`

=== 3. `ARITY_MISMATCH` (Mismatch Numero Argomenti)

**Origine:** `StepperScheme.istanziaCorpoChiusura` / Primitive native (`src/lib/scheme/runtime/stepper.ts`)

Lanciato quando il numero di argomenti forniti in un'applicazione non corrisponde al numero dei parametri formali dichiarati dalla chiusura o richiesti dalla funzione primitiva.

**Formato del messaggio:**
`Arity mismatch: attesi <N> argomenti, ricevuti <M>.`

=== 4. `TYPE_ERROR` (Errore di Tipo Runtime)

**Origine:** Primitive d'ambiente (`ambienteStandard.ts`, `ambientePerDivisione.ts`, ecc.)

Lanciato quando l'argomento passato a una primitiva non soddisfa il tipo atteso (es. operazione aritmetica su stringhe o navigazione di liste su non-liste).

**Esempi:**
- `'<operatore>' richiede argomenti numerici.`
- `'primo' richiede una lista non vuota.`
- `La condizione di 'if/se' non si riduce a un booleano.`

=== 5. `ENVIRONMENT_NOT_FOUND` (Profilo Ambiente Inesistente)

**Origine:** `creaAmbiente` (`src/lib/scheme/runtime/registroAmbienti.ts`)

Lanciato come istanza della classe personalizzata `AmbienteNonTrovatoError`.

**Formato del messaggio:**
`Ambiente con id "<idAmbiente>" non trovato tra i profili predefiniti.`

=== 6. `EXECUTION_LIMIT` (Superamento Limite Passi)

**Origine:** `StepperScheme.passiDaSorgente` / `passiStream` (`src/lib/scheme/runtime/stepper.ts`)

Lanciato per prevenire cicli infiniti durante la riduzione di ricorsioni non terminanti.

**Formato del messaggio:**
`Limite massimo di <maxPassi> passi raggiunto.`

== Mapping DTO suggerito per Frontend / Web UI

[source,typescript]
----
export type CodiceErroreScheme =
  | 'SYNTAX_ERROR'
  | 'UNDEFINED_SYMBOL'
  | 'ARITY_MISMATCH'
  | 'TYPE_ERROR'
  | 'ENVIRONMENT_NOT_FOUND'
  | 'EXECUTION_LIMIT'
  | 'INTERNAL_ERROR';

export interface ErroreInterpreteDTO {
  codice: CodiceErroreScheme;
  messaggio: string;
  dettagli?: string;
  passoCorrente?: number;
}
----
